## 決定と導入条件

①選択と合成の共通計画、②原音・遷移を保持する経路を実装した。
歌詞モードは `--lyrics-renderer source` が既定。従来の辞書式選択とWORLD合成は `--lyrics-renderer world` で選べる。
今回の採用条件はシステムアプリ・システムDLL・コンパイラの追加導入を不要にすること。

| 候補 | 調査・実行結果 | 判断 |
| --- | --- | --- |
| `praat-parselmouth` | 通常の設定済みindexから0.4.7のWindows wheelを仮想環境に導入できた。Praat 6.1.38を内蔵。Pythonから解析とoverlap-add合成が動作 | 採用。PraatアプリやPATH設定は不要 |
| `pyrubberband` | PythonラッパーだけではRubber Band実行ファイルを満たさない | 採用しない |
| `rubband` | 0.3.1の公開ファイルはmacOS ARM64 / CPython 3.11のwheelとsdist。現Windows環境で`--only-binary :all:`を指定した導入は利用可能版なし | ソースビルド・システム導入はせず見送り |
| 同梱ffmpegのrubberbandフィルタ | フィルタは存在するが、今回必要な時間対応表と動的ピッチの組み合わせの経路を提供しない | 今回の代替経路にはしない |

依存は[pyproject.toml](../pyproject.toml)と[uv.lock](../uv.lock)に追加した。
`[tool.uv] no-build-package = ["praat-parselmouth"]` で、そのwheelがない環境のソースビルドを抑止する。
既存のCPU/CUDA extra、パッケージindex、プロキシを変更していない。実行環境には追加パッケージのみ導入し、GPU依存の同期・交換はしていない。
Rubber BandのWindows wheelが将来利用可能になる可能性までは否定しない。

公式資料: [Parselmouth導入](https://parselmouth.readthedocs.io/en/stable/installation.html)、[ピッチ操作](https://parselmouth.readthedocs.io/en/stable/examples/pitch_manipulation.html)、[rubband配布ファイル](https://pypi.org/project/rubband/#files)、[pyrubberband](https://pypi.org/project/pyrubberband/)。
依存のライセンス情報は[同梱物の説明](../THIRD_PARTY_LICENSES/README.md)へ追記した。

## ① 選択と合成を一致させる構造

実装: [source_synth.py](../src/madgen/source_synth.py) の `AnalysisStore` / `TransformPlan` / `make_plan`、[match.py](../src/madgen/match.py) の `select_source_plans`。

1. デコード済み44.1 kHz・モノラルの音源を使用する。元の圧縮音声やステレオまで復元する意味ではない。
2. 同一音源の近接音素をまとめて解析する。0.25秒超の空き、または15秒超で分割し、前後150msを付ける。旧DBには発話IDがないため、今回の解析範囲はこの規則で決め、ターゲット音符には依存させない。60ms未満の録音は解析のみゼロ埋めし、使用音声には含めない。
3. PraatでF0を一度解析する。5ms刻み、60〜1100 Hz。解析で得た実時刻・F0・無声の0値・局所RMSを`.npz`へ保存し、同じPitchから作ったパルス・波形を含む`.Manipulation`を保存する。`Sound + Pitch → Manipulation`を使用し、Manipulationの作成時や合成時にF0を推定し直さない。初期案のDIO共有ではなく、合成用パルスと整合するPraat解析を選んだ。
4. 使用範囲、出力開始・サンプル数、時間対応表、目標F0点、参照F0、実移調量を候補ごとに確定する。短く切る設定では切った後の範囲を評価する。
5. 候補の移調コストは有声フレームの目標との差、伸縮コストは時間対応表の局所倍率から計算する。DBの旧F0中央値や全区間の長さ不足率で代用しない。
6. 選んだ計画オブジェクトを変更せず合成へ渡し、同じ内容を`plan.json`の`transform`へ書く。合成側でコア抽出・候補選択・F0再推定はしない。

キャッシュは`DB名.cache/source-v1/`。キーは音声ファイルの内容ハッシュ、解析範囲、サンプルレート、F0設定、解析スキーマ版、Praat/Parselmouth版を含む。既存DBを書き換える専用移行や音素モデルの再実行は不要。
計画の再利用には対象の音声・解析キャッシュが必要であり、JSON単体の再生CLIはまだ提供しない。

### 探索範囲とコスト

- 音素の順位・確信度の既存コストで上位200件を粗く選び、前段候補の元録音上の後続候補を加える。粗選択に旧F0は使わない。
- `4 × 音素コスト + 加工コスト` の上位50件と、後続候補内の上位50件を残す。1段あたり最大100候補に制限する。
- 加工コストは平均絶対移調量/100 cents、最大`abs(log2(局所伸縮率))`、伸縮しないときの不足率。有声定常部のない全体伸縮は伸縮項を重くする。F0のない母音には制約を表す加算を行い、架空のF0は作らない。補正を無効にした場合の音程項は、残る目標との誤差を評価する。
- 元録音・出力で正確に連続し、まとめて合成できる場合の接続コストは0、それ以外は0.5。50ms超の楽譜の休符では接続項を課さない。

辞書式の絶対優先から重み付き和へ変えた。ただし係数の聴取による最適化は未実施。同点の多い大きなコーパスでは、粗い上位200件の外に良い候補が残る可能性がある。加工後の境界スペクトルやクリックを採点したものでもない。

## ② 原音と遷移の扱い

実装: `render_group` / `render_plans`、[render.py](../src/madgen/render.py) の `_render_source_voice`。

- **無加工**: ピッチ補正なし、時間対応が1対1なら、元波形を直接読む。隣接した区間の内部にフェード・音量調整を入れない。
- **連続素材**: 元音源と出力の両方でサンプル単位で連続し、ゲインが同じ区間はまとめる。加工時は同じ解析範囲であることも必要。複数音符のF0目標を同じPitchTierへ載せ、一度の合成で処理する。
- **時間加工**: 母音・撥音では大きく有声な最長部分を伸縮可能部とし、それ以外の入口・出口・減衰を捨てず残す。両端には最低20msの保護を試みる。保護部分が音符に収まらない場合、または有声定常部のない素材は全体を伸縮する。対応点と実際の倍率に反映し、隠れて切り捨てない。
- **ピッチ加工**: 有声子音を含めて、検出した有声部分を目標F0へ寄せる。`flatten=0`は元の相対変動を保ち、1は平坦化。補正しきい値は使用範囲の全有声フレームに対して確認する。無声部分のF0補間による有声化は行わない。
- **Praat**: overlap-add合成（有声部分はTD-PSOLA）。元波形・パルスを使い、WORLDのスペクトル再構成や非周期性の上限制限は通らない。時間対応はDurationTierの積分へ変換する。比率切替はサンプル未満の対称ランプにし、積分後の終点を保つ。
- **音量と境界**: 音素ごとのRMS正規化や子音-6dBを行わず、独立した素材グループの外縁のみ5msフェードする。別素材の重ね合わせによる高度な接続最適化は未実装。トラックゲイン、EQ、自動伴奏バランス、最終ピーク正規化とPCM16出力は既存どおり。

加工時は原音波形と完全一致するわけではない。PSOLAの窓で発音境界がぼけること、Praat内部で平均値が除かれること、高音や不安定な周期の誤推定は残る。出力長は厳密に検証し、不足した場合に無断でWORLDへ切り替えたりゼロ埋めしたりせずエラーにする。

## 検証

自動テストは **101件通過**、Ruff・`git diff --check`・`uv lock --check --offline`も通過。追加のテストは[tests/test_source_synth.py](../tests/test_source_synth.py)、既存歌詞テストにはsource/world両方のCLI出力検証を追加。

| 検証 | 結果 |
| --- | --- |
| 無加工の分割・再接続 | 外縁フェードとミックス前の波形でサンプル完全一致。通常の外縁フェードを有効にしても内部境界は変わらない |
| 意図的にDBのF0を逆にした候補選択 | 実使用波形のF0で正しい候補を選んだ |
| 0.5 / 1 / 2 / 4倍の長さ + 220→330 Hz | 出力サンプル数が一致、独立したFFT測定が目標範囲内 |
| 同一素材の連続2区間へ異なるF0を適用 | まとめた合成で両方の音程を確認 |
| 伸縮しない短い使用範囲・休符 | 計画の切断範囲と出力が一致、休符へはみ出しなし |
| 25msの無声録音 | 解析用パディングを出力せず原音コピー可能。無声のまま時間変更可能 |
| 有声音から無音への出口位置 | 時間対応表からの予測と、実波形の有声音末尾の差が20ms未満。末尾の無音を保持 |
| キャッシュ | 別Storeから再利用でき、音声内容変更でキー更新。合成時に再解析しない |

実素材比較は[検証スクリプト](research/validate_source_renderer.py)で実施した。既存DBはSQLiteの`mode=ro`で読み、認識モデル/GPUは使わず、2つのDBから異なる音源の母音を各3件選んだ。

```powershell
uv run --no-sync --offline --cache-dir .uv-cache python docs/research/validate_source_renderer.py --db work/corpus_sample.sqlite --out work/source-render-validation/sample
uv run --no-sync --offline --cache-dir .uv-cache pytest -q
uv run --no-sync --offline --cache-dir .uv-cache ruff check
```

加工は元の有声F0中央値から+3半音、全体長2倍、平坦化1。F0の測定は合成用Praatとは別のWORLD Harvest。有声判定されたフレームに限った誤差であり、無声フレームを誤差0として数えていない。高音の26622（目標約660 Hz）は重点試聴例として残す。

WORLDは使用コア・ゲイン・末尾20msが異なるため、この比較は**経路全体の出力確認**であり、加工条件を統一したエンジンの音質ランキングではない。音声はまだ聴取評価していない。6件は品質を代表する統計評価でもない。
