# WORLD歌詞合成: 使用コアの共有と子音の調整

2026-09-20。mainのWORLD経路で、[改善点一覧](lyrics-implementation-review.md)の優先度1（R01・R02）と2（R06・R11・R12の一部）を実装。Praatブランチの合成エンジンは使用せず、依存も追加しない。

## 使用コアとF0を選択・合成で共有する

`WorldPlanStore` が候補の44.1 kHz音声を、従来と同じ前後30 ms付きでDIO/StoneMask解析する。WORLDの既存のコア検出を共通関数へ切り出し、大きく有声な部分を選ぶ規則は維持した。

音符より長いコアは、実際に合成で残す先頭のフレーム数へ切り詰めてからF0中央値を計算する。候補の音程コストにはその中央値、伸長コストには実際の出力フレーム数÷使用コアフレーム数を使う。従来の区間全体のF0・長さは、母音のこの評価には使わない。

音素・音程と長さ・接続という辞書式の優先順位は維持する。音素コスト最良の同点候補をすべて解析するため、古いDBのF0で候補を事前に落とさない。伸長コストは `ceil(3 * log2(伸長倍率))`、最大10。半音単位の音程コストと足し合わせる。重みの聴取最適化は未実施。

選択済みの `CorePlan` を `NoteJob` に渡し、合成時は保存したF0系列・解析時刻・コア範囲を実行する。F0推定とコア検出のやり直しはない。スペクトル・非周期性の解析は選ばれた音にだけ行う。

WORLDの母音処理（低域の非周期性制限、無声F0補間、スペクトルエネルギー調整、音量正規化、20 msの末尾）は維持する。ただし、長いコアを切る場合の基準F0・エネルギー統計は実使用部分のものになるため、同じ素材でも音が変わる場合がある。

## 子音の切り出し・配置・増幅

- WORLDの子音は引き続き原波形を使用し、ピッチ補正・時間伸縮をしない。
- `t/k/p` などの無声破裂音では1 msごとのエネルギー上昇を調べる。直前5 msの平均より4倍以上の明確な上昇があり、素材冒頭から3 ms以上経っている場合、その立ち上がりの2 ms前まで先頭を切る。検出できなければ注釈開始位置を使う。摩擦音・破擦音・有声子音にはこの切り出しを適用しない。
- 使用可能な波形を既存の子音枠以内に収める。短い場合、直後に母音・撥音が接しているときだけ枠の末尾へ寄せ、母音までの不要な隙間をなくす。休符や単独子音の位置は動かさない。
- 音量は5 ms窓のうち最大エネルギーの10%以上の窓で計算する。静かな閉鎖区間を平均へ含めて破裂を過剰に増幅しない。従来の子音目標音量を使いつつ、増幅を最大6 dBに制限する。
- 端のフェードを入口1 ms・出口2 msにし、短い子音の大部分が従来の20 msフェードに消費されることを避ける。

これは息と破裂を完全に識別するモデルではない。強いノイズを立ち上がりと誤認する可能性や、息を含んだ素材が残る場合がある。後続母音とのCV遷移生成、子音枠自体の可変長化、促音の高度な処理は未実装。

## 使用方法・再現性

比較音声の聴取でユーザーから改善の確認と既定化の承認を得たため、既定を `core/aligned` にした。オプション省略時も新処理を使用する。従来処理は `--lyrics-selection legacy --lyrics-consonants legacy` で選べる。

| 比較目的 | オプション |
| --- | --- |
| 従来のWORLD | `--lyrics-selection legacy --lyrics-consonants legacy` |
| 優先度1だけ | `--lyrics-selection core --lyrics-consonants legacy` |
| 優先度2だけ | `--lyrics-selection legacy --lyrics-consonants aligned` |
| 両方 | `--lyrics-selection core --lyrics-consonants aligned` |

`--no-lyrics-stretch` の場合はコア合成を使わないため、コアを使う選択も無効化する。子音の調整は別に切り替えられる。USTのピッチカーブ対応は今回含まない。

DB横の `.cache/world-core-v1/` に解析を保存する。音声ファイル内容のSHA256、解析用範囲、対象区間、WORLD版、解析定数と方式版をキーにする。既存DBの再構築は不要。選択と合成の間に入力音声を変更しないことを前提にする。

`plan.json` に `world_core`（解析キー、読込範囲、使用フレーム、F0、出力長、伸長倍率）と `world_consonant`（使用サンプル範囲、実配置、ゲイン、先頭切り出し有無）を記録する。コアの使用時刻はWORLDフレーム中心から得た範囲であり、スペクトル分析窓の参照範囲全体ではない。映像の時間変形は今回変更しない。

## 比較音声

`docs/research/compare_world_improvements.py` は既存WORLD出力の素材IDとUSTの正確な時刻を使い、次の5種類を作る。

| 番号 | 内容 |
| --- | --- |
| 00-legacy | 従来の素材・従来の合成を再現 |
| 01-core-fixed | 素材IDを固定し、共有コア計画だけ適用 |
| 02-consonants-fixed | 素材IDを固定し、子音調整だけ適用 |
| 03-core-selected | コアに基づく再選択と共有コア合成、子音処理は従来 |
| 04-combined | 再選択・共有コア・子音調整をすべて適用 |

全比較で旧伴奏と共通の音量倍率を使用し、比較別のピーク正規化や自動伴奏バランス調整はしない。必要なら全比較へ同じヘッドルーム倍率を掛ける。音声合成を含めて再実行した比較であり、元の書き出しWAVとのサンプル一致を前提にしない。

```powershell
uv run --no-sync --offline --cache-dir .uv-cache python docs/research/compare_world_improvements.py --full
```

出力は `work/world-improvements/`。各方式の `*-mix-18-30.wav` と `*-vocals-18-30.wav`、従来と両方適用の全曲、加工計画を含む `comparison.json` を保存する。元の音声は上書きしない。

通常CLIの新処理の全曲確認は `work/world-improvements-cli/`。現在の既定である `--lyrics-selection core --lyrics-consonants aligned` と同じ設定でUSTのみを標準の選択・合成・書き出し経路へ通した。そのミックスは比較音声とマスター倍率が異なる。

## 検証

実曲の全857ユニットで比較を完了。コアに基づく選択で492ユニットの素材が変更された。母音の伸長倍率は中央値2.00→1.06、90パーセンタイル4.10→2.23、最大12.50→4.65。絶対移調量は中央値53.0→68.8 centsと増え、90パーセンタイルは225.0→182.5 centsに減った。音程の近さだけでなく伸長負担も評価するため、すべての指標が単調に改善するものではない。

「はさみでタイムライン」のt（ユニット40、素材ID16214）は素材固定の子音比較でも同じ素材を使う。従来は2648サンプル（約60.0 ms）、調整後は1020サンプル（約23.1 ms）を母音直前へ配置。立ち上がり検出で先頭を切り、ゲインは約+3.05 dB。両方適用の全曲では49子音で先頭切り出しを行い、子音増幅の最大値は6 dBだった。

全比較で共通マスター倍率1.27622、追加ヘッドルーム倍率1.0。ミックスのピークは従来約0.8912、両方適用約0.8759で、全音声は有限値・クリップなし。通常CLIも857ユニットを完走し、比較スクリプトと素材選択が一致、記録したコアF0・伸長倍率と合成結果の一致を確認した。初回の比較では9113候補のコアを解析。キャッシュ再利用時の通常CLI全曲出力は約2分7秒だった。

数値の詳細は[測定結果](research/world-improvements-results.json)、ローカル出力の `verification.json` を参照。

全98テスト・Ruffを通過。追加・拡張テストで、DBとコアのF0が異なる候補の選択、短いコアへの過剰伸長回避、長いコアの切り捨て後のF0、合成時のF0再推定禁止、独立したFFTによる出力音程、音声変更時のキャッシュ無効化、破裂の保持、母音とのサンプル単位の接続、増幅上限、休符保持、CLIの4組み合わせを検証した。

自然さや滑舌が改善したかは試聴で判断する。実装上の整合性を確認したことと、音質が改善したことは区別する。
